## Definition of Done

The Definition of Done is part of the Scrum Guide. It describes the quality an increment must meet before it counts as done. If a backlog item does not meet it, it goes back to the Product Backlog and is not shown at the Sprint Review as finished.

Agree it as a team, write it down, and review it in retrospectives. If several teams work on one product, they share one Definition of Done.

Starting checklist. Delete what does not apply and add what your product needs.

- [ ] Code reviewed by at least one other developer
- [ ] Automated tests written and passing
- [ ] Acceptance criteria met and checked by someone other than the author
- [ ] No known critical or high-severity defects
- [ ] Security and privacy checks done for any change that touches user data
- [ ] Documentation and release notes updated
- [ ] Deployed to an environment where stakeholders can see it
- [ ] Product Owner has seen it working

---

## Definition of Ready

The Definition of Ready is a team practice and is not in the Scrum Guide. Use it as a checklist for refinement, not as a gate that blocks work. If it starts blocking good work, shorten it.

- [ ] Clear user or business value stated
- [ ] Acceptance criteria written and testable
- [ ] Dependencies identified, with an owner for each
- [ ] Small enough to finish within one sprint
- [ ] Estimated by the people who will do the work
- [ ] No open question that blocks starting
